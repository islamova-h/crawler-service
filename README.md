# Crawler

Небольшой HTTP-микросервис на Go, который принимает список URL и параллельно проверяет доступность веб-страниц.

Проект выполнен в учебных целях для практики работы с HTTP, конкурентностью в Go, `context`, таймаутами, worker pool и структурированным логированием.

## Возможности

* HTTP-сервер на порту `8080`
* `POST /crawl` для запуска краулинга
* Приём списка URL в формате JSON
* Worker Pool из **5 воркеров**
* Ограничение количества одновременно выполняемых задач
* HTTP-запросы с поддержкой `context`
* Таймаут **3 секунды на каждый URL**
* Отмена обработки при отмене контекста клиентского запроса
* Получение HTTP-статуса и размера тела страницы
* Структурированные JSON-логи в `stdout`
* Уровни логирования `INFO`, `WARN`, `ERROR`
* Передача `trace_id` через `context`
* Graceful shutdown HTTP-сервера
* Unit-тесты основных компонентов

## Как это работает

Клиент отправляет `POST`-запрос на `/crawl` со списком URL.

```json
{
  "urls": [
    "https://example.com",
    "https://github.com"
  ]
}
```

URL передаются в worker pool. Пул состоит из пяти воркеров, поэтому одновременно обрабатывается не более пяти адресов.

Упрощённо схема работы выглядит так:

```text
                  POST /crawl
                       │
                       ▼
                ┌─────────────┐
                │   Handler   │
                └──────┬──────┘
                       │
                       ▼
                  Jobs channel
                       │
          ┌────────────┼────────────┐
          ▼            ▼            ▼
       Worker 1     Worker 2     Worker 3
          │            │            │
          │            │            └── ...
          │            │                 Worker 5
          └────────────┼──────────────────┘
                       ▼
                 Results channel
                       │
                       ▼
                  JSON response
```

Для каждого URL создаётся HTTP-запрос с контекстом и таймаутом 3 секунды.

Если клиент отменяет свой запрос, контекст отменяется, и воркеры прекращают обработку новых задач.

## API

### `POST /crawl`

Запускает обработку переданных URL.

#### Request

```json
{
  "urls": [
    "https://example.com",
    "https://github.com"
  ]
}
```

#### Response

```json
{
  "results": [
    {
      "url": "https://example.com",
      "status": 200,
      "length": 1256
    },
    {
      "url": "https://github.com",
      "status": 200,
      "length": 185432
    }
  ]
}
```

Поля результата:

* `url` — обработанный URL;
* `status` — HTTP-статус ответа или статус ошибки;
* `length` — размер полученного тела ответа в байтах.

Для ошибок обработки используются:

* `500` — внутренняя ошибка;
* `503` — сайт недоступен или запрос завершился по таймауту.

## Логирование

Сервис использует структурированные JSON-логи, которые записываются в `os.Stdout`.

Пример:

```json
{
  "time": "2026-08-27T19:30:12Z",
  "level": "INFO",
  "trace_id": "7c1e8c4e-7d5a-4c7b-a2d4-123456789abc",
  "message": "crawl started"
}
```

Используются следующие уровни:

| Level   | Назначение                      |
| ------- | ------------------------------- |
| `INFO`  | начало и завершение краулинга   |
| `WARN`  | таймаут или недоступность сайта |
| `ERROR` | ошибка разбора входного JSON    |

`trace_id` передаётся через `context` и используется для связи логов одного запроса.

## Тестирование

Для тестирования используются стандартные инструменты Go:

* `testing`
* `httptest`
* тестовые HTTP-серверы
* `context`
* table-driven tests

Тесты разделены по основным компонентам приложения.

### HTTP-клиент

Тестируется:

* успешный HTTP-запрос;
* получение статуса `200`;
* корректное определение размера тела ответа;
* таймаут запроса;
* отмена контекста.

Пример тестового сервера создаётся с помощью `httptest.NewServer`.

### Worker Pool

Тестируется:

* успешная обработка нескольких URL;
* конкурентная обработка задач;
* работа с отменённым контекстом;
* обработка пустого списка URL.

### HTTP Handler

Тестируется:

* успешный `POST /crawl`;
* корректный JSON-ответ;
* пустой список URL;
* некорректный JSON;
* неправильный HTTP-метод.

Запуск всех тестов:

```bash
go test ./...
```

Для запуска тестов с детектором гонок:

```bash
go test -race ./...
```

## Запуск

Требуется Go.

Клонировать репозиторий:

```bash
git clone <repository-url>
cd crawler
```

Запустить сервер:

```bash
go run ./cmd/server
```

Сервис будет доступен по адресу:

```text
http://localhost:8080
```

## Пример использования

```bash
curl -X POST http://localhost:8080/crawl \
  -H "Content-Type: application/json" \
  -d '{
    "urls": [
      "https://example.com",
      "https://github.com",
      "https://google.com"
    ]
  }'
```

## Graceful Shutdown

При получении `SIGINT` или `SIGTERM` сервер выполняет graceful shutdown.

Это позволяет корректно завершить текущие HTTP-запросы перед остановкой приложения.

Для остановки сервера локально:

```text
Ctrl+C
```

## Цель проекта

Основная цель проекта — на практике разобраться с конкурентной обработкой HTTP-запросов в Go и научиться управлять жизненным циклом задач с помощью `context`.

Проект объединяет несколько важных для backend-разработки концепций Go в одном небольшом сервисе.
